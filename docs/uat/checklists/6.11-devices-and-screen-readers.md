# 6.11 checklist — public pages on real devices and with screen readers

The parts of story 6.11 that automation cannot reach: real phones, the desktop
browsers as people install them, a real print dialog, a person running the
guide's samples, and real screen readers. It covers PP-01, PP-02, PP-03 (by
hand), PP-05, PP-06, PP-07 and PP-08 (`docs/uat/test-plan.md`, "Acceptance
criteria — PP") on the four public pages:

- `https://orizons.xyz/guide/list-your-agent` (v1.1.0)
- `https://orizons.xyz/demo`
- `https://orizons.xyz/litepaper` (v0.5)
- `https://orizons.xyz/evidence`

**Already automated — do not repeat in desktop Chromium.** axe scans, the
360 px layout check and Chromium print are in the frontend e2e suite; this
repo's `tests/public-pages.spec.ts` (PP-01, PP-02, PP-05, PP-06, the structure
half of PP-07, PP-08's long name), `tests/guide-samples.spec.ts` (PP-03) and
`tests/litepaper-formats.spec.ts` (PP-04) run in Chromium, WebKit and Firefox
engines. Those engines are not the devices: every step below **is** run on the
real phones and the installed desktop browsers, including desktop Chrome.

Work through it in order and fill in every **Record** field as you go. Results
go into `docs/uat/evidence/6.11-public-pages.md`; screenshots are named
`6.11-<device>-<step>.png` (for example `6.11-iphone-A3.png`), with `<device>`
one of `iphone`, `android`, `chrome`, `firefox`, `safari`. Copy expected text
*exactly* as quoted: a difference is a finding, even a small one.

## Rules

- **Production URLs only.** `https://orizons.xyz/…`, never a preview or local
  build.
- **No account, no wallet.** Use a private / incognito window with no wallet
  extension enabled and no orizons.xyz login. Every public page must work like
  that; needing either is a failure, not a precondition.
- **Consent.** Several agents on `/app/agents` and on `/evidence` belong to
  outside operators. Never write their agent id, wallet or transaction hash
  anywhere: not in the evidence file, a screenshot name, a defect or a chat
  message. Describe them by position ("the third card on `/app/agents`", "the
  second row of the evidence table") and crop or blur them out of screenshots.
  Team identifiers (`uat624_ext_op`, the QA reference agent from 6.09) are
  recorded in full.
- **Team agent only.** The guide samples run against `AGENT_ID=uat624_ext_op`,
  never an outside operator's agent.
- **Do not work around a failure.** If a step fails on one device, record what
  it showed and carry on with the next device.
- **A defect is a linked Bug.** Every failure gets a screenshot, the device and
  the browser (with versions). Record the screenshot path in the evidence file
  and send it to the lead, who logs it in `docs/uat/defects.md` and gives you
  the `D-0NN` to write back into the result cell.

matrix. Phones in portrait first, then landscape for A2 only. Desktop windows at
their normal size, then narrowed as far as the browser allows for A2.

| # | Where | Do | Expect | Record |
| --- | --- | --- | --- | --- |

## B · JavaScript off, no wallet (PP-02)

Turn JavaScript off for the browser, then repeat B1–B3 for each of the four
pages. Turn it back on before moving to C.

| Browser | How to disable JavaScript |
| --- | --- |
| Chrome (desktop) | DevTools (F12) → Command menu (Ctrl/Cmd+Shift+P) → "Disable JavaScript" (lasts while DevTools stays open), or Settings → Privacy and security → Site settings → JavaScript → "Don't allow sites to use JavaScript". |
| Firefox | `about:config` → `javascript.enabled` → `false`. |
| Safari (macOS) | Settings → Advanced → "Show features for web developers" (Develop menu), then Develop → Disable JavaScript. |
| iOS Safari | Settings → Apps → Safari → Advanced → JavaScript off. |
| Android Chrome | Chrome → ⋮ → Settings → Site settings → JavaScript → off. |

| # | Where | Do | Expect | Record |
| --- | --- | --- | --- | --- |
| B1 | the page, reloaded with JavaScript off | Confirm JavaScript is off (on the guide the copy buttons now do nothing), then scroll the whole page. | The same sections as in A1 render with their full text. No "enable JavaScript" wall, no empty area where content should be, no spinner. | pass/fail · screenshot `6.11-<device>-B1-<page>.png` |
| B2 | same | Follow the page's links and download links again. | They all work: none needs a script. On `/demo` the video either plays or offers a plain link to YouTube; the list of how to verify each deliverable is readable. | anything that stopped working |
| B3 | `/guide/list-your-agent` | Press a copy button. Then select a sample's text by hand and copy it. | The copy buttons may do nothing; that is the only thing allowed to be inert. Selecting the text by hand works and copies the whole command. | copy button behaviour · manual copy pass/fail |

Anything other than the guide's copy buttons that needs JavaScript is a PP-02
failure: record which page, which element, and what it showed.

## C · Three guide samples, by hand (PP-03)

Desktop Chrome, JavaScript on, and a terminal. The guide marks the samples that
can be checked against the live testnet with `verify="live"` in the page source
(View source, search `verify="live"`). Use three of them, for example the
network check, `binding-read` and `readiness`. **Do not run `ecosystem-adoption`**:
it is the report behind open defect D-091 and takes over five minutes.

Set the guide's variables once, in the same terminal:
`export ORIZON_API=https://orizons.xyz/api`, `export AGENT_ID=uat624_ext_op`
(a team agent; never put an outside operator's agent id here).

| # | Where | Do | Expect | Record |
| --- | --- | --- | --- | --- |
| C1 | `/guide/list-your-agent` | Pick three `verify="live"` samples. | Three different samples, none of them `ecosystem-adoption`. | the three sample names and the guide section of each |
| C2 | same, then the terminal | For each sample: press its **copy** button, paste into the terminal without editing, run it. | The command runs as pasted: no stray prompt character (`$`), no smart quotes, no missing line continuation. | each command as pasted · anything you had to edit |
| C3 | terminal | Compare each output with the response block the guide prints under the sample. | Same fields, same types, same fixed values (for example `"network": "testnet"`). Values that change by nature (times, nonces, ledger numbers) may differ; the guide should say which ones do. | each output (only `uat624_ext_op` and team values) · each difference, field by field |
| C4 | the guide | For any difference in C3, read what the guide says about that field. | The guide explains it, or the difference is a finding. | finding per sample, or "matches" |

PP-03 passes when all three samples ran as copied and matched their documented
responses. A sample that needed editing to run, or answered differently, is a
defect against the guide.
