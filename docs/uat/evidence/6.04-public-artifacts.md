# 6.04 OV-05 evidence — the public artifacts, with no wallet and no session

Run 2026-10-02 against <https://orizons.xyz>, frontend `origin/main`
`0c8a10b7`. Spec: `tests/public-artifacts.spec.ts`.

**OV-05:** the registration page, the integration guide and the demo video are
each opened in a fresh context with no wallet and no session, and each is
fully reachable.

## How "fresh" was made

Each test opens its own Playwright browser context and asserts it is empty
before it navigates: no cookies, no stored origin data. That is a private
window. The suite's Chromium has no wallet extension installed, so no wallet
can be present. Each context is closed when its test ends.

Every page is checked for:

- an HTTP 200 on the navigation;
- its own `<h1>` and the content a visitor came for, read by role;
- no console error and no uncaught page error from load to network idle,
  using the suite's shared collector (`collectConsoleErrors`, which ignores
  only favicon, analytics-beacon and extension noise).

## The guide's links

`/guide/list-your-agent` carries 311 anchors: 114 in-page fragment links (the
table of contents, step cross-references and the friction-log appendix), 26
external links, and links to 11 internal pages (`/`, `/app`, `/app/agents`,
`/app/flow`, `/app/orchestrator`, `/app/reputation`, `/app/trace`, `/demo`,
`/evidence`, `/guide/list-your-agent`, `/litepaper`). The test reads every
`a[href]` from the rendered page, not from a fixed list. It asserts:

- every in-page fragment names exactly one element with that `id`;
- every internal page answers below 400 to the same fresh, session-less
  context.

Both guide pages pass. External links (GitHub, Stellar Expert, friendbot) are
not this site's to keep and are not checked.

## The guide is a draft, and says so

The guide's frontmatter reads `status: draft` (`content/guides/list-your-agent.md`).
The page states it in words, as a `role="note"` above the steps: "Draft — not
yet validated by a newcomer. The steps below have been checked by the team but
not yet followed end to end by someone new to Orizon." The index entry ends
"· draft". That honesty is asserted, so a draft that stopped saying so would
fail.

**Does it matter for "published"?** For OV-05, no: OV-05 asks whether the
guide is reachable, and it is. For SOW milestone m09 ("Public 'List your agent
on Orizon' integration guide published"), it is a risk. The guide is public at
a stable URL, so in the plain sense it is published, but by its own words it
is not finished, and a reviewer reading "Draft — not yet validated" can
reasonably decline to accept it. The guide drops the note when the frontmatter
reads `status: validated`, after a newcomer has followed it end to end. Filed
as **D-NEW-PUB-2** and pinned by a `test.fail()`.

## The demo video: what is actually there

Nothing yet. `/demo` is built at deploy time from `content/demo/demo.json`,
which reads:

```json
{ "status": "unpublished", "video": null, "chapters": [], "transcript_file": null, "captions_file": null }
```

The page handles that honestly. It renders `data-demo="unpublished"` and a
`role="note"` reading "The demo video has not been recorded yet. It will show
only real testnet transactions. Until then, here is how to verify each
deliverable yourself." It follows that with a "Verify each deliverable
yourself" list and links to the evidence bundles. There is no `<video>`, no
`<iframe>`, and no staged footage. The repo holds the production plan
(`content/demo/script.md`, `shot-list.md`, `narration.txt`), but not the
recording.

So OV-05 **fails for the demo video**: the page is reachable, but the artifact
OV-05 names does not exist, and SOW milestone m10 ("3–5 min demo video
published") is not met. Filed as **D-NEW-PUB-1** and pinned by a
`test.fail()`, which will pass unexpectedly once the manifest is published and
the player's iframe is on the page.

## Spec results

`tests/public-artifacts.spec.ts`, 9 tests, run live on 2026-10-02:

| project | result |
| --- | --- |
| chromium-desktop | **9 passed** (2.7 min) |
| chromium-mobile (Pixel 7) | 8 passed, then the registration test passed on re-run after its time budget was raised to cover a cold backend |

Two of the nine are `test.fail()` pins and pass by failing: the demo video
(D-NEW-PUB-1) and the guide's validated status (D-NEW-PUB-2).

**Chromium only.** The browser cache on the authoring machine holds only
`chromium-1243` and its headless shell, and Firefox and WebKit will not
download there (D-025). `playwright.config.ts` still declares
`webkit-desktop` and `firefox-desktop`, so those projects will run this spec
unchanged on a machine that has them. They were not run here, so this is not
cross-browser sign-off.

## Defect drafts (for the lead; `defects.md` is not edited here)

**D-NEW-PUB-1 — The demo video is not recorded, so /demo has nothing to play.**
Severity: Major (it blocks SOW m10 and the video third of OV-05). Steps: open
`https://orizons.xyz/demo` in a private window. Expected: a 3–5 minute video
in a player. Actual: `data-demo="unpublished"`, no `<video>` or `<iframe>`,
and the notice "The demo video has not been recorded yet."
`content/demo/demo.json` has `"video": null`. The page itself is correct and
honest. The missing piece is the recording, plus a published manifest.
Pinned by `OV-05 the demo video is published on /demo and its player is on the page`.

**D-NEW-PUB-2 — The integration guide is public but self-declared a draft.**
Severity: Minor (a risk to SOW m09 acceptance, not to reachability). Steps:
open `https://orizons.xyz/guide/list-your-agent`. Expected for "published": a
guide a newcomer has validated. Actual: frontmatter `status: draft`, and a
note above the steps reading "Draft — not yet validated by a newcomer". The
resolution is a newcomer run-through, then `status: validated`. Pinned by
`OV-05 the integration guide is published as validated, not as a draft`.

## OV-05 verdict

**Fail, on one of three artifacts.** The registration page and the
integration guide are fully reachable with no wallet and no session. The demo
video does not exist yet (D-NEW-PUB-1). The guide's draft status (D-NEW-PUB-2)
does not affect OV-05, but it puts m09's "published" at risk.
