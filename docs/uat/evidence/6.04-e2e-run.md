# 6.04 evidence — OV-08, one validation workflow end to end on the deploy

Run 2026-10-02 on testnet, by `tools/e2e-run/run.py` (one command, see its
README), against the deployed backend `https://orizon-agents-be-stellar.onrender.com`
(escrow v2 `CCNO5TENCK3EK532I3OZLZ63323FEEULPAKJ74CUP3JZK3XQINRQ5VC4`, asset
native XLM). The buyer is UAT's own throwaway testnet key
`GCIGBMIUJGGQ6WRX3A7GMZGAESBPY76W5IBZDZHF3K6J3FNJIYHYGTQX`, funded by friendbot;
its secret was never in the repository.

**Verdict: OV-08 is Blocked.** The run's artifacts are captured at the moment
and resolve on Stellar Expert, but no workflow on the deploy can complete: every
agent with an on-chain owner that the planner can route to has a bound endpoint
that does not answer a dispatch (§3). So the task fails, the settle pays nobody
and returns the custody, and no seal is ever written. A run with a `charged`
payout and a seal is not reachable from UAT today (D-077).

## 3 · Why no workflow on the deploy can complete

A step is paid only when its agent has an on-chain owner, and an agent is only
dispatched to through its bound endpoint. `GET /api/agents` on 2026-10-02 lists
six agents with `bound: true`, all with an on-chain owner. The backend's own
`GET /api/agents/{id}/readiness` probe of each one's endpoint:

| Agent | Price | Bound host | `reachable` |
| --- | --- | --- | --- |
| `algorex` | 0.01 | `testing.com` | failed — "answered 301, a redirect. Dispatches never follow redirects." |
| `Powerbot` | 0.12 | `powerbot.com` | done — a web page answers, but not the dispatch protocol: the 2026-10-01 run on it failed the same way (§4) |
| `3D_Artbot` | 50.0 | `arbot.com` | failed — "did not answer within 5 s" |
| `faulty_test_v2` | 0.2 | a Cloudflare quick tunnel | failed — hostname no longer resolves; also below the 5500 bps routing floor |
| `uat624_ext_op` | 0.01 | a Cloudflare quick tunnel | failed — hostname no longer resolves |
| `uat605_ext_op` | 0.01 | a Cloudflare quick tunnel | failed — hostname no longer resolves |

The agents the backend's own 5.01 team runs paid (`calculatorai`, `keyboardai`)
are no longer bound. The seeded `agt_*` agents have no on-chain owner, so the
tool refuses a plan that routes to them before signing: a settle could pay them
nothing. The settler's account on Horizon shows no paid settle since
2026-09-30; its only transactions since are UAT's released runs below.

UAT's own operator endpoint (`tools/operator-endpoint/server.ts`, as in 6.05)
could stand in, but it needs a public HTTPS tunnel to be dispatched to, and no
tunnel was available to this run. With one, the run is: bind
`uat624_ext_op` to the tunnel (owner-signed challenge), then run the tool with
an intent naming its skill (`haiku`, `uat624`).

## 5 · Defect drafts

Drafted for the lead to file; ids are placeholders.

**D-077 — No paid workflow can complete on the deploy: every owned, bound
agent's endpoint is dead.** Urgent (money path). Steps: list `GET /api/agents`;
probe each `bound: true` agent with `GET /api/agents/{id}/readiness`; run the
tool with any intent the planner routes to one of them. Expected: at least one
routable agent with an owner answers a dispatch, so a buyer's run is delivered,
`settle` pays its owner (a `charged` event) and the job is sealed. Actual: five
of six fail the backend's own `reachable` probe and the sixth (`Powerbot`) is a
web page, not an operator; every run fails, `settle` pays nobody, nothing is
sealed (§1, §3, §4). OV-08 cannot pass until a live operator is bound.

**D-084 — The planner routes to, and the buyer pays fees for, an agent its
own readiness probe already reports unreachable.** Medium. Steps: decompose
"run an algorithm reasoning task with algorex"; read
`GET /api/agents/algorex/readiness`. Expected: an agent whose `reachable` step
is `failed` is passed over like an unbound one (the planner already excludes
`unbound_endpoint` and below-floor agents), or the plan warns before the buyer
signs. Actual: the plan routes to `algorex`; the buyer signs an authorize, the
step fails in 0.3 s, and the buyer pays two transactions' fees for a run that
could not be delivered (§1). The tool's own gate shows the check is cheap.
