## 2 · Write-once: the re-seal probes

`seal` checks the caller against the stored sealer first (`Unauthorized = 1`),
then whether the job exists (`AlreadyExists = 3`), and `get` fails
`NotFound = 2` on an unknown job (contracts repo,
`contract/attestation-registry/src/lib.rs`). A probe by a random key would stop
at the sealer check and prove nothing about write-once. So each probe is an
unsigned `seal(...)` with the **sealer** GDB4N…CDHP as both the transaction
source and `caller`, simulated with `authMode: "record"`: the source account
satisfies `caller.require_auth()` without a signature, and the call reaches
the existence check. The arguments are the claimed attestation itself.

| Probe | Result | What it shows |
| --- | --- | --- |
| sealer re-seals each of the 5 sprint jobs | `Error(Contract, #3)` AlreadyExists, all 5 | the stored seal blocks a second write |
| sealer seals a fresh random job id with the same arguments (control) | simulates cleanly, 1 auth entry (the sealer's) | the probe itself is valid, so #3 comes from the stored seal and not from the arguments |
| former sealer GA7AI…5OQV seals h1's job | `Error(Contract, #1)` Unauthorized | the 2026-09-19 `set_sealer` hand-over holds; the old key cannot seal |
| `get` on a fresh random job id | `Error(Contract, #2)` NotFound, no ledger entry | an unknown job is an error, not an empty attestation |
| sealer re-seals each of the 8 archived pre-sprint jobs (§4) | `Error(Contract, #3)`, all 8 | write-once survives archival: the simulation restores the entry on the fly and the existence check still sees it |

After 2026-10-07 the data is not lost. An archived entry stays in the hot
archive, `getLedgerEntries` returns it with no live-until ledger, and a
simulated `get` still answers (the 8 pre-sprint seals, §4, read this way).
What lapses is the live state: block explorers and plain ledger reads show the
seals as archived, and the next transaction that touches them pays to restore
them. The spec therefore checks each entry's live-until ledger before `get`, and
fails with "seal archived, restore needed" instead of passing on restored data.
