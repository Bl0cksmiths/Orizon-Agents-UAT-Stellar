## 2 · Registration and binding pages, without a wallet prompt

Observed with Playwright on the deployed dApp (`tests/operator-surfaces.spec.ts`,
chromium-desktop).

**Two-signature disclosure (OS-03).** On `/app/register`, with no wallet and
nothing clicked, the page already reads, directly above `Register agent ▸`:

> ▸ two signatures, one at a time — Listing an agent takes two signatures. This
> one is the on-chain registration transaction. Binding an endpoint afterwards
> takes a second, separate signature — a signed message that proves you own the
> agent. It moves no funds and costs no fee.

Before the first prompt, and says what the second signature is for. It does not
say that some offered wallets cannot make that second signature (D-046).

**Refused endpoints (OS-06).** Typed into `/app/bind`'s `endpoint url`, no wallet:

| endpoint | preflight answer | page | bind button |
| --- | --- | --- | --- |
| `http://example.com/dispatch` | `scheme_not_https` | `⚠ endpoint URL … uses scheme 'http'; only ['https'] allowed · rule: scheme_not_https` (`role=alert`) | disabled |
| `https://10.0.0.5/dispatch` | `non_public_address` | message names the private range `· rule: non_public_address` | disabled |
| `https://localhost/dispatch` | `loopback_host` | `· rule: loopback_host` | disabled |
| `https://127.0.0.1/…`, `https://[::1]/…`, `https://169.254.169.254/…` | `non_public_address` (API) | — | — |
| `https://orizon-uat-no-such-host-606.invalid/dispatch` | **`allowed: true`** | **`✓ endpoint allowed`**, no refusal | **enabled** (wallet session stubbed) |

The unresolvable host is refused only by `POST /bind`, after the owner signs
(D-043).

**Rebind (OS-05, page half).** `/app/bind?agent=uat605_ext_op` as its owner
shows the current binding's host (`profiles-confident-plot-acm.trycloudflare.com`,
as `GET /api/agents/uat605_ext_op/binding` returns it), relabels the field
`replacement endpoint url`, says *"Binding replaces the endpoint above. Work
already routed keeps the endpoint it was routed to; everything after this lands
on the new one."*, and offers `Replace endpoint ▸`. That a rebind succeeds and
the new endpoint reads back is proven at the API level by 6.05 (two rebinds,
`replaced: true`, read-back matched); the in-browser signing half is checklist
section C.
