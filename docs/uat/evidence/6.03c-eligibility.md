## 1 · What could run on the deploy

Every scenario in the card starts from a settled step, and none exists: `DP-01`
still fails as expected on 2026-09-25 (D-050, behind D-039). The one exception is
the reason, which the service checks before it looks the job up. Probed live
against `https://orizon-agents-be-stellar.onrender.com` with an unsettled job:

| Reason sent | Answer |
| --- | --- |
| `""` | `422 validation_error`, `string_too_short` on `reason` |
| `" \t\n "` | `422 reason_required`, message `"reason required"` |
| `"\u200b"` (one zero-width space) | `404 unknown_job` — the reason check passed (D-059) |
| 500 × `é` (1000 bytes) | `404 unknown_job` — inside the cap, which counts characters |
| 501 × `x` | `422 validation_error` on `reason` (`DR-03`) |

These are asserted on every suite run by `tests/dispute-eligibility.spec.ts`;
the two invisible-character cases are `test.fail()` pinned to D-059.

The window shortcut in the card (settle with `DISPUTE_WINDOW_SECONDS=120`) was
not used: it needs a settlement, and a Render setting change only the operator
can make.
